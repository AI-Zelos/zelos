# 06 — Architecture Delta

## Beyond Code Changes

A code diff tells you **what lines changed**. An Architecture Delta tells you **what the system changed**.

When an AI modifies code, reviewers need to know:
- Which modules are affected?
- Are there new dependencies?
- Did any APIs change? Are they backward compatible?
- Did the data model change?

## Architecture Delta Structure

```json
{
  "modified_modules": ["auth-service", "user-model"],
  "new_dependencies": ["oauthlib==3.2.0"],
  "removed_dependencies": ["legacy-auth-lib"],
  "api_changes": [
    {"endpoint": "POST /auth/oauth", "change_type": "new", "compatibility": "additive"}
  ],
  "data_model_changes": ["users.add(oauth_provider, oauth_id)"],
  "risk_level": "medium",
  "explanation": "Standard OAuth2 addition, isolated to auth module"
}
```

## Risk Levels

| Level | Criteria | Action |
|-------|----------|--------|
| `low` | Additive change, no breaking API, one module | Auto-approve possible |
| `medium` | Multiple modules, new dependencies | Auto-approve with caution |
| `high` | Core module changes, data model migration | Human review mandatory |
| `critical` | Payment/auth/security, breaking API changes | Architect + security review |
| `unknown` | Planner cannot determine | Human review mandatory |

## Auto-Generation

Architecture Delta is **auto-generated by the Planner** (LLM). The LLM prompt includes a schema for arch_delta alongside tasks. If the LLM cannot determine the impact, it marks `risk_level = "unknown"` and the Policy Gate escalates to human review.
