# Zelos v1.0.0 需求规格说明书

> 核心主题：**CP（Change Proposal）完整落地** — Zelos 成为论文"从 PR 到 CP"的完整参考实现。
>
> v1.0 标志着 Zelos 从"执行引擎 + 治理原型"升级为"AI 原生软件变更治理平台"。

---

## 一、为什么要做 v1.0

### 现状（v0.9.1）

Zelos 实现了 CP 理念的骨架（Intent → Evidence → Confidence → Decide），但论文定义的 5 个核心设计有 3 个未落地：

| 论文 CP 设计 | v0.9.1 现状 |
|-------------|-----------|
| CP 五元信息模型 I×K×S×R×E | ❌ 散落在各处，无统一建模 |
| 约束固化 + 可控生成 | ❌ Agent 自由执行，无约束绑定 |
| 证据核验 → 合规合并 | ⚠️ PolicyGate 有决策，无合并执行 |
| Verifier 自动编排 | ❌ 手动配置，未与 CP 绑定 |

### 目标

v1.0 让 Zelos 成为论文中 CP 设计理念的**完整工程实现**。

## 二、需求清单

### REQ-10：ChangeProposal 一等对象（P0）

**背景**：论文定义 CP 为五元信息模型 I×K×S×R×E 的可执行治理对象。当前 Zelos 无此对象。

**需求**：

1. 新增 `ChangeProposal` dataclass，包含论文五元：
   - `intent: IntentSpec` — 变更意图
   - `knowledge_constraints: dict` — 知识约束（编码规范、技术栈限制）
   - `structural_constraints: dict` — 结构约束（架构边界、依赖白名单、API 规范）
   - `risk_spec: dict` — 风险规范（风险等级阈值、安全要求）
   - `verification_criteria: dict` — 验证准则（测试通过率、覆盖率门槛、Benchmark 基线）

2. `ChangeProposal.to_dict()` / `from_dict()` 往返序列化。

3. `submit_goal()` 自动构建 `ChangeProposal` 对象，存为 Goal 的核心治理对象。

4. `ExecutionReport` 的 `change_proposal` 字段替换原有的分散字段。

**验收**：CP 对象完整包含五元、可序列化往返、与 ExecutionReport 集成。

---

### REQ-11：约束引擎（P0）

**背景**：论文要求"约束固化"——变更的约束规则在代码生成前被锁定，形成可执行的 AI 生成规则。

**需求**：

1. 新增 `ConstraintEngine`，输入 `ChangeProposal`，输出 `ExecutableConstraints`：
   - 编码规范（lint 规则、格式化要求）
   - 架构边界（禁止修改的模块、允许的依赖范围）
   - 风险阈值（性能基线、安全等级、覆盖率门槛）
   - API 契约（必须保持兼容的接口 Schema）

2. `ConstraintEngine.apply(cp)` 返回固化后的约束对象。

3. 约束对象可注入到 Agent 执行上下文中。

**验收**：ConstraintEngine 正确解析 CP 五元、输出可执行约束。

---

### REQ-12：约束注入——可控生成（P0）

**背景**：论文要求 AI 代码生成"受前置固化的约束规则管控"。

**需求**：

1. `ExecutionEngine.dispatch()` 在派发 Task 前，从 Goal 的 CP 中提取约束，注入 `input_context`。

2. `Task` 新增 `constraints: dict | None` 字段，携带可执行约束。

3. Agent 执行时可读取 `Task.constraints` 约束自己的行为。

4. 向后兼容：无 CP 的 Goal 保持旧行为。

**验收**：Agent 收到的 Task 包含约束字段；约束注入不影响旧 Goal。

---

### REQ-13：Verifier 链自动编排（P1）

**背景**：论文定义核验为 `E = Verify(CP, Artifact)`，且核验链应根据 CP 的 verification_criteria 自动选择 Verifier。

**需求**：

1. 新增 `VerifierChain` 类，输入 `ChangeProposal.verification_criteria`，自动选择并排序 Verifier。

2. 链执行规则：任一 Verifier FAIL → 链停止，Task 标记验证失败。

3. 核验结果归入 `EvidenceBag`。

4. 置信度低于阈值时，自动追加 Verifier（verification escalation）。

**验收**：Verifier 链根据 CP 自动编排；FAIL 阻断；escalation 生效。

---

### REQ-14：自动合并执行（P1）

**背景**：论文定义 `Merge(CP, Artifact) = True ⇔ Policy(CP, Evidence) = True`。当前 PolicyGate 能做决策但不会执行合并。

**需求**：

1. `auto_decide()` 返回 `auto_approve` 时，Runtime 自动执行合并动作。

2. 新增 `MergeExecutor`：支持 `git merge` / `event_sourcing_apply` 两种策略。

3. 合并前创建 Rollback 快照（event_sourcing snapshot）。

4. 合并失败 → 自动回滚到合并前状态。

**验收**：auto_approve → 自动合并；失败 → 自动回滚。
