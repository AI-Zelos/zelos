## Abstract

A Change Proposal — also called CAR (Change Approval Request) — is the **next-generation Pull Request**. It replaces the code-centric PR with a change-centric proposal: Intent, Architecture Delta, Impact Analysis, Evidence, Risk Assessment, and Rollback Plan. Code is supporting evidence, not the primary artifact.

## Motivation

The traditional PR was designed for humans writing hundreds of lines. When AI produces 40,000+ lines per change, the code diff becomes unreadable. CAR shifts the review target from **code** to **change**.

## Specification

### CAR: 10 Mandatory Modules

| # | Module | Answers |
|---|--------|---------|
| 1 | Intent | What problem does this solve? What is explicitly out of scope? |
| 2 | Requirement Mapping | Which requirements does each code change serve? |
| 3 | Architecture Delta | What modules/dependencies/APIs changed? |
| 4 | Implementation Plan | What are the rollout steps? |
| 5 | Impact Analysis | What systems are affected? |
| 6 | Evidence | Tests, benchmarks, security scans, coverage — all quantified |
| 7 | Risk Assessment | Risk level, root cause, mitigation plan |
| 8 | Rollback Plan | Exact steps to revert, estimated downtime |
| 9 | Generated Artifacts | API diffs, DB migration scripts, benchmark reports |
| 10 | Human Decision | Architecture/Business/Risk/Deployment decisions — no "LGTM" |

### CAR Generation

CAR is **auto-generated by the Runtime**, not manually authored:

```
Planner Agent → Change intent + plan
Code Agent → Code diff + module changes
Test Agent → Test results + coverage
Security Agent → Vulnerability scan
Performance Agent → Benchmark data
Architecture Agent → Impact analysis
        ↓
Runtime aggregates → Complete CAR document
Human reviews → Approves/Rejects the change, not the code
```

### CAR vs Traditional PR

| Dimension | Traditional PR | CAR |
|-----------|---------------|-----|
| Primary artifact | Code diff | Change proposal |
| Description | Optional, brief | Mandatory, structured |
| Evidence | Ad-hoc | Typed, quantified, collected automatically |
| Risk | Not required | Mandatory with mitigation plan |
| Rollback | Not required | Mandatory with steps + duration |
| Reviewer role | Read code, find bugs | Evaluate evidence, approve change |
| AI-ready | No (designed for human-scale) | Yes (designed for AI-scale) |

### Rules

1. **All 10 modules are mandatory.** Missing any → rejection.
2. **No vague descriptions.** "Tests passed" is insufficient — must state counts.
3. **Risk ≥ medium requires mitigation plan and rollback strategy.**
4. **Code is an attachment, not the primary artifact.**
5. **CAR is an Event** — review decisions are immutable and replayable.
